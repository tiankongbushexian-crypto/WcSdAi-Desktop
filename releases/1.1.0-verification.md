# WcSdAi 1.1.0 release verification

> [!WARNING]
> **Do not install WcSdAi 1.1.0. Security patch 1.1.1 is being prepared.**
> A high-severity Undici failure in the Agent networking dependency has been reproduced: an affected response can terminate the subprocess and interrupt tasks. Do not downgrade to 1.0.5 as a security workaround; it contains the same affected dependency. No credential disclosure or code execution has been demonstrated. See the [updated security assessment](#security-hold-and-dependency-assessment).

Verification date: 2026-10-25 (Asia/Shanghai). The checks below record the original native gates, production activation and public-release verification. A subsequent security reproduction supersedes the earlier promotion decision: 1.1.0 installation is paused while 1.1.1 is prepared. Successful build and functional checks do not establish vulnerability absence.

## Application and account checks

Desktop JS build, TypeScript, lint, architecture, workspace tests, Rust format,
Clippy and all 732 host tests passed. Documentation checks and 53 packaging /
credential-probe harness tests passed. The updated PR integration checks passed.

The final isolated account scenario uses actual Renderer actions, preload,
Electron Main, Rust Host persistence, Node agent runtime, loopback PKCE callback,
Go authorization and PostgreSQL. It passed login, allowed-model synchronization,
zero-balance denial, admitted streaming after synthetic credit, token refresh and
logout preserving the session. The upstream model is synthetic. The locked local
Mac used an explicitly reported test-only in-memory encryption fixture; it is not
OS secure-storage evidence and has no production fallback switch.

Separate native gates use disposable copies of the final packaged Electron
executable and the actual account encryption module. Two process starts verify
OS encryption and decryption without reading an installed user profile. This is
not a claim that a real user's complete payment/login flow was exercised on each
operating system.

Gateway authorization, replay protection, device ownership, model/group access,
personal-key compatibility, checkout handoff, payment-resume and cleanup tests
passed, including targeted race checks. Real isolated PostgreSQL tests verified
atomic rotation, additive migrations, idempotent payment fulfillment, pre-credit
denial, post-credit admission and idempotent usage debit. Website TypeScript,
related tests and production asset build passed; the clean Linux/amd64 embedded
binary was built and its version executed in the production container without
starting a second application.

## Compatibility and limits

The existing API providers, vendor OAuth, local sessions, configuration and
permissions remain available. Account logout disables only its managed providers;
it does not erase conversations. Personal API keys are not confused with Desktop
credentials, even with the feature gate disabled. No upgrade requires deleting
application data. Prices and billing mode are unchanged.

The integration advertises validated conversational/agent protocols. Media-only,
realtime, embeddings and ambiguous composite model aliases are not represented
as validated account chat models. Linux source compatibility remains, but no
native Linux release certification or Linux installer is claimed here.

No real payment-provider settlement, real paid upstream model request or upgrade
of the operator's installed app was performed. These remain unsigned team builds.
macOS ad-hoc bundle integrity does not constitute Developer ID signing or Apple
notarization. Windows has no publisher code-signing certificate.

The full Gateway Go suite is not globally green on the operator's Mac. Three
unchanged failures reproduce on the original baseline: a Linux-assumption reauth
test, an old site-name expectation and exact floating-point equality. Eight
unchanged mihomo fixtures timed out under the full parallel run but pass in
isolation on both baseline and candidate; their timeout cause is not established.
No unrelated business formula was changed to conceal these failures.

## Security hold and dependency assessment

Five dependency advisories are currently recorded: **one high, three medium and one low**. The previous two-alert summary was incomplete and is superseded by this assessment.

| Dependency | Severity | Advisory | Assessed exposure |
| --- | --- | --- | --- |
| Undici 8.10.2 | High | [GHSA-xjj6-f33q-929c / CVE-2026-109869](https://github.com/nodejs/undici/security/advisories/GHSA-xjj6-f33q-929c) | Process-termination failure reproduced with a synthetic local HTTP response; the affected package is used in Agent networking. |
| Undici 8.10.2 | Medium | [GHSA-4qv8-2p9j-2685 / CVE-2026-109924](https://github.com/nodejs/undici/security/advisories/GHSA-4qv8-2p9j-2685) | Included in the affected package; this application's use of the advisory's EventSource/SRI prerequisites has not been established. |
| Undici 8.10.2 | Medium | [GHSA-f72v-6w45-q472 / CVE-2026-109841](https://github.com/nodejs/undici/security/advisories/GHSA-f72v-6w45-q472) | Included in the affected package; this application's use of the advisory's EventSource/SRI prerequisites has not been established. |
| Vitest 3.2.7 | Medium | [GHSA-82fw-gwwq-j7x9](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9) | Mock-development-server file-read prerequisites; this application uses `vitest run` without that exposed server configuration. |
| KaTeX 0.16.47 | Low | [GHSA-238p-pmpm-9mq7](https://github.com/KaTeX/KaTeX/security/advisories/GHSA-238p-pmpm-9mq7) | Production Renderer restriction bypass requiring prior prototype pollution. The sanitizer runs before KaTeX and is not claimed as an after-render defense. |

The high-severity Undici reproduction ran the actual 8.10.2 package in an isolated Node subprocess against a synthetic localhost response. The response supplied more than five content encodings and closed early after declaring its content length. An unhandled error still terminated the process with exit code 1 after the fetch rejection was caught. No production model, payment service or real user's credentials were used in this reproduction.

The Agent uses this npm package for image-result downloads and for global model fetches when a custom proxy is configured. Affected responses can therefore interrupt the Agent subprocess and its tasks. **Credential disclosure and arbitrary code execution have not been demonstrated.** The two other Undici advisories are included in the package-level security repair; no application use of their additional API prerequisites was established in this review.

**Do not install 1.1.0 while security patch 1.1.1 is prepared and validated.** Downgrading to 1.0.5 is not a recommended security workaround because it contains the same affected dependency. The published source, checksums and historical verification evidence remain available; their integrity does not eliminate the dependency vulnerability.
