## Application and account checks

Desktop JS build, TypeScript, lint, architecture, workspace tests, Rust format,
Clippy and all 732 host tests passed. Documentation checks and 53 packaging /
credential-probe harness tests passed. The updated PR integration checks passed.

The final isolated account scenario uses actual Renderer actions, preload,
Electron Main, Rust Host persistence, Node agent runtime, loopback PKCE callback,
Go authorization and PostgreSQL. It passed login, allowed-model synchronization,
zero-balance denial, admitted streaming after synthetic credit, token refresh and
logout preserving the session. The upstream model is synthetic. The locked local
Mac used an explicitly reported test-only in-memory encryption fixture; it is not
OS secure-storage evidence and has no production fallback switch.

Separate native gates use disposable copies of the final packaged Electron
executable and the actual account encryption module. Two process starts verify
OS encryption and decryption without reading an installed user profile. This is
not a claim that a real user's complete payment/login flow was exercised on each
operating system.

Gateway authorization, replay protection, device ownership, model/group access,
personal-key compatibility, checkout handoff, payment-resume and cleanup tests
passed, including targeted race checks. Real isolated PostgreSQL tests verified
atomic rotation, additive migrations, idempotent payment fulfillment, pre-credit
denial, post-credit admission and idempotent usage debit. Website TypeScript,
related tests and production asset build passed; the clean Linux/amd64 embedded
binary was built and its version executed in the production container without
starting a second application.

## Compatibility and limits

The existing API providers, vendor OAuth, local sessions, configuration and
permissions remain available. Account logout disables only its managed providers;
it does not erase conversations. Personal API keys are not confused with Desktop
credentials, even with the feature gate disabled. No upgrade requires deleting
application data. Prices and billing mode are unchanged.

The integration advertises validated conversational/agent protocols. Media-only,
realtime, embeddings and ambiguous composite model aliases are not represented
as validated account chat models. Linux source compatibility remains, but no
native Linux release certification or Linux installer is claimed here.

No real payment-provider settlement, real paid upstream model request or upgrade
of the operator's installed app was performed. These remain unsigned team builds.
macOS ad-hoc bundle integrity does not constitute Developer ID signing or Apple
notarization. Windows has no publisher code-signing certificate.

The full Gateway Go suite is not globally green on the operator's Mac. Three
unchanged failures reproduce on the original baseline: a Linux-assumption reauth
test, an old site-name expectation and exact floating-point equality. Eight
unchanged mihomo fixtures timed out under the full parallel run but pass in
isolation on both baseline and candidate; their timeout cause is not established.
No unrelated business formula was changed to conceal these failures.

Two pre-existing dependency alerts remain open. Vitest 3.2.7 has a mock-development
server file-read advisory; this application uses `vitest run` without that exposed
server configuration. KaTeX 0.16.47 is included in the production Renderer and has
a restriction-bypass advisory requiring prior prototype pollution. The current
sanitizer runs before KaTeX, so it is not claimed as an after-render defense. No
newly reachable exploit chain was identified in this account change; this is not
a statement that the product is vulnerability-free. See the
[Vitest advisory](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9)
and [KaTeX advisory](https://github.com/KaTeX/KaTeX/security/advisories/GHSA-238p-pmpm-9mq7).

## Publication evidence

All three native installer jobs in run `40171748162` passed. Both macOS
architectures passed ad-hoc bundle integrity and OS Keychain probes. Windows
passed OS DPAPI probes, native corner-region checks and six initial/light/dark
packaged corner-pixel/hit tests. A CSS-only negative control was correctly rejected.
Windows evidence is from Windows Server 2025 / build 26100, Electron 43.6.0 at
100% scaling; it does not certify every Windows 11 device or scaling combination.

The Gateway was activated with Desktop disabled, verified, then enabled and
verified again. All 314 historical migration checksums were retained, with exactly
two reviewed migrations added (316 total). PostgreSQL and Redis were not restarted;
shared Nginx was not changed. Billing mode remained standard, prices, balances,
personal keys, groups and settings matched the private preflight snapshot. Live
upstream credential/extra metadata changes were preserved; a private comparison
confirmed unchanged account identities, platform/type and multipliers. No stale
snapshot was restored over live business data.

A fresh private backup includes the complete database, configuration and previous
runtime. Archive listing and full payload decoding passed; this is not a restore
rehearsal. The preferred recovery keeps the new binary and disables Desktop routes.
It never restores an old database or silently starts a legacy binary over managed
credentials. The app-only deployment helper passed 24 interruption/recovery tests.

Anonymous HTTPS verification passed for four pages and 15 exact static assets,
including authorization and recharge. The public version matched the candidate,
and the anonymous Desktop bootstrap returned 401. No real user's login, payment
or paid model request was used for this verification.

The three complete ZIPs match GitHub artifact sizes/digests. Every inner checksum
and BUILD-INFO entry was verified; all contain the same corresponding source and
notices. The seven release assets passed local size/SHA-256 validation, and all
eight uploaded files (including SHA256SUMS) matched GitHub's server-side digests.
Distribution validation regression tests passed 14/14. The release manifest and
checksums identify each exact file; automated GitHub source ZIPs are distribution
metadata, not the application source.
