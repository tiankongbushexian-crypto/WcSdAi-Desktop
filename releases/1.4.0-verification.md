## Observable changes

- Supported installed clients can discover a signed release, view its notes, download inside the app, verify its package, and explicitly choose Install and restart.
- A cached download does not install on ordinary exit. Live/cached unsent drafts, pending attachment operations, active work, approvals, and unsafe persistence prevent installation until resolved.
- Checkpoint/outbox completion, plugin shutdown and Host exit precede the native installer handoff. Successful handoff alone is not success: the expected version, installation path and ready Host must be observed on restart.
- Signed metadata binds version, architecture, immutable website URL, size and hashes. Mac additionally verifies the native Sparkle archive signature. Private signing keys stay outside Git, CI, installers and the server.
- Account identity, billing, API settings, personal model parameters and sessions retain their existing formats and ownership. No database migration or automatic database rollback is introduced.
- The 1.3.2 usability corrections remain included: reveal output files in their containing folder, Windows interface-format selection, and one-row account action buttons.

## Scope and remaining limits

Clients at 1.3.2 or earlier need one manual installation of 1.4.0 from https://api.90z.cn/download. Later supported updates use the in-app path. An already-current client does not reinstall the same version.

Windows native installation currently supports an unambiguous registered current-user NSIS installation. All-users, portable and mismatched paths retain manual download. Mac requires a writable installed bundle, not a DMG or translocated copy. Update signatures authenticate release content; they do not provide Apple Developer ID/notarization or a Windows publisher certificate and do not bypass operating-system trust decisions.

Crash or OS force termination cannot be intercepted. Once the user authorizes native preparation, an already authorized Mac installation can finish on exit. A failed or unconfirmed cancellation retains the safety barrier and distinct feedback. Recovery preserves user data; no automatic database downgrade is promised.

The initial signed-feed publisher creates a previously absent feed atomically. Later release replacement or 180-day renewal requires a reviewed compare-and-swap operation binding the previous signed-envelope hash, new signature and packages. Renewal is an operator responsibility, not a background automation installed by this release.
