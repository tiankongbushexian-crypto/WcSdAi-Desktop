# WcSdAi 1.0.3 verification

## Candidate and scope

Prepared on 2026-10-03 in the request worktree `codex/wcsdai-macos-tray`,
based on `e71c148ff308178eab5e1b321dac773bd1983fae` (`origin/main` at
preparation). All three native 1.0.3 installers are now built, downloaded and
verified as recorded below. The owner's Apple Silicon Mac also completed the
real installed-app manual upgrade with startup, data continuity and update
recheck verified. The owner subsequently supplied a menu-bar screenshot and
rejected the visual size/alignment. The [1.0.4 follow-up](1.0.4-verification.md)
records the correction; the successful upgrade and data checks below remain
valid for 1.0.3.

The 1.0.3 macOS menu-bar design enlarged and attempted to optically center the mark on a transparent
26×22pt template canvas. Native 1x and 2x images preserve clarity on Retina.
The visible mark is approximately 23.24×16pt with a 1.25pt downward optical
offset. The ordinary rounded application icon, home animations, tray menu
actions and Windows/Linux tray appearance keep their existing behavior.
No updater implementation, Host data schema, Session format, provider setting,
permission or credential migration is part of this fix.

The installed application was 1.0.2 when the owner requested a real
Check for Updates → download → manual installation journey for this fix.
Preparing a locally built app or directly replacing the installed application
does not satisfy that acceptance path. The verified 1.0.2 download links and
`updates/stable.json` were retained during implementation and package checks.
The metadata follow-up published verified 1.0.3 artifacts to `main`; the agent
then completed the requested installed-app journey as recorded below.

## Validation plan and risks

- Reuse the existing Node/pnpm/Electron dependencies and Cargo build cache.
  Isolate profiles, fixtures, logs and artifacts in the request worktree.
- Validate the generated transparent 1x/2x PNGs, their scale representations,
  native template mode and macOS package resource paths. The principal visual
  risks are missing 2x packaging, pixel scaling and optical placement; verify
  the menu-bar result under light/dark appearance on a Retina display.
- Run the targeted tray image tests, existing native tray interaction tests,
  release metadata/changelog checks, applicable build/type checks and
  `node scripts/e2e-macos-tray.mjs` with its disposable profile. Record the
  exact candidate and base before candidate acceptance; PR integration must
  preserve that executable tree or receive fresh validation.
- Build macOS arm64, macOS x64 and Windows x64 packages from the integrated
  commit. Download the actual artifacts and verify source commit, version,
  identity, checksums, licenses/notices and expected package contents. Verify
  both tray images in each macOS app, and retain the existing unsigned-team
  policy: macOS ad-hoc integrity sealing is separate from Developer ID signing
  and notarization; Windows has no publisher signature.
- Exercise startup and restart of the downloaded Apple Silicon app using a
  disposable fixture profile. Intel and Windows static package inspection
  does not prove installation or existing-data upgrades on those devices.

No real provider calls, credential inspection, production server deployment,
Git tag or GitHub Release are required by these checks. Preserve the existing
profile and Host data throughout the manual upgrade recorded below.

## Installed-app manual upgrade — passed

On 2026-10-03 (Asia/Shanghai), the agent completed the owner's requested
upgrade through the existing installed application and normal Finder installer
workflow:

1. Settings → Info in 1.0.2 checked the fixed public feed and showed 1.0.3 with
   its release notes. Its download button started the matching GitHub artifact
   ZIP download in Chrome. The downloaded ZIP digest matched
   `7a43d598c971101f6eeb14853ffb91ec987fb6dbe46d202bcfe10d618ef0ad2d`;
   the included DMG checksum and matching source were also verified.

   full backup of Host data, Electron profile and the old app passed source/copy
   hash, file-mode and compatibility-link checks. No private backup path or
   data contents are published here.
3. Finder copied the verified DMG's application to Applications using Replace.
   Before first launch, all Host/profile bytes and compatibility aliases matched
   the stopped backup. Installed executable, ASAR, Host and both tray image
   hashes matched the downloaded package, and `codesign --verify --deep --strict`
   passed. Installed native version fields were 1.0.3.
4. The first launch was blocked by Gatekeeper. At that action, the owner
   explicitly authorized Open Anyway for WcSdAi 1.0.3 only. The native System
   Settings action allowed this application; global security settings were
   unchanged. The installed app then started normally.
5. Info showed application and Host 1.0.3 with protocol 11. Existing projects
   and Sessions were visible. A post-launch read-only database `quick_check`
   returned `ok`; project, Session, message and provider counts matched the
   pre-upgrade baseline. No credential values were read or printed.
6. Check for Updates visibly moved through checking to the latest-version
   result. The application remained running as the installed 1.0.3 build.
