# WcSdAi 1.0.4 verification

Validated on 2026-10-03 (Asia/Shanghai) using the request worktree
`codex/wcsdai-macos-tray`, with Node 22.23.3, pnpm 12.8.1, Rust 1.98.1 and
Electron 43.6.0 on macOS 26.5 arm64. Native package jobs used their own clean
macOS arm64/x64 and Windows x64 runners.

## Scope and authorization

The owner supplied screenshots showing that the 1.0.3 Mac menu-bar symbol was
too large and vertically unbalanced, and that Windows desktop/taskbar/tray
symbols were too small. The Windows desktop icon also had an unwanted opaque
white tile. The owner approved the revised preview, including Windows variant
A: a transparent black symbol with a thin white outline. This approval covers
the proposed artwork; it does not replace native package or runtime validation.

The owner explicitly chose to perform the next local upgrade themselves.
Publishing 1.0.4 must not quit, replace, relaunch or change a security exception
for their installed application. Test-owned Electron instances use disposable
profiles. Existing data, configuration, provider credentials, permission
settings and sessions remain outside this work. No API calls to real providers
are required.

The logo's original vector paths remain intact. The Windows tray has no white
outline or tile; its system-selected black or white fill provides contrast.
Changing the app content theme must not override the system tray appearance.
The tray controller owns the appearance subscription and removes it during
normal shutdown. Missing assets and native update failures remain observable
without blocking application startup. Tray menu actions, window restoration,
explicit quit, native identifiers, the updater protocol and persistence are
unchanged.

## Limits and compatibility

The owner approved the preview. Resource geometry, native tray behavior and
package inspection passed, but they do not substitute for installed visual
acceptance across operating systems and DPI settings. Intel and Windows
installation, existing-data upgrades and native visual checks remain pending.
The owner's local 1.0.4 installation is intentionally owner-managed. The agent
did not quit, replace, relaunch or grant an OS exception for the installed app.
The [1.0.3 report](1.0.3-verification.md) preserves the prior manual-upgrade
history and later visual feedback.

No provider requests or user data were used. `verify:ui:*` was not authorized
and was not run. Host persistence, IDs, data paths, session format, permissions,
provider configuration and the updater protocol are unchanged. The only Host
change is its release version. No installer automatically installs itself.

Packages remain unsigned team builds: macOS uses an ad-hoc integrity seal,
without Developer ID or notarization, and Windows has no publisher signature.
No Git tag, GitHub Release or server deployment was created. Actions downloads
require GitHub login and expire at the times above. Evidence is retained in
the ignored `.artifacts/wcsdai-icon-platforms/` directory; no private backup,
credential or user-database content is included in this report.
