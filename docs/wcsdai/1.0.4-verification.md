# WcSdAi 1.0.4 verification

## Scope and authorization

Prepared on 2026-10-03 (Asia/Shanghai) in the ongoing request worktree
`codex/wcsdai-macos-tray`. The preceding public update metadata landed at
`f0df8e566ec39c8fdcad90c61e28d8142435be26`. Record the actual fixed candidate
and refreshed base below before publishing; this initial report is not a claim
that the new packages or tests have passed.

The owner supplied screenshots showing that the 1.0.3 Mac menu-bar symbol was
too large and vertically unbalanced, and that Windows desktop/taskbar/tray
symbols were too small. The Windows desktop icon also had an unwanted opaque
white tile. The owner approved the revised preview, including Windows variant
A: a transparent black symbol with a thin white outline. This approval covers
the proposed artwork; it does not replace native package or runtime validation.

The owner explicitly chose to perform the next local upgrade themselves.
Publishing 1.0.4 must not quit, replace, relaunch or change a security exception
for their installed application. Test-owned Electron instances use disposable
profiles. Existing data, configuration, provider credentials, permission
settings and sessions remain outside this work. No API calls to real providers
are required.

The logo's original vector paths remain intact. The Windows tray has no white
outline or tile; its system-selected black or white fill provides contrast.
Changing the app content theme must not override the system tray appearance.
The tray controller owns the appearance subscription and removes it during
normal shutdown. Missing assets and native update failures remain observable
without blocking application startup. Tray menu actions, window restoration,
explicit quit, native identifiers, the updater protocol and persistence are
unchanged.

## Implementation checks executed

Using the existing Node 22.23.3, pnpm 12.8.1, Rust 1.98.1 and Electron
43.6.0 environment on macOS 26.5 arm64:

- `python3 scripts/make-icon.py` regenerated and validated 17 monochrome
  assets with the already available Pillow and Sharp dependencies.
- Six targeted desktop test files passed **46/46** tests, covering Mac
  bounds/Retina representations, Windows ICO pixels and DPI frames, controller
  lifecycle/theme updates, tray actions and packaged resource contracts.
- The old Windows icon fails the new transparent-background assertion; the
  old Mac tray fails the new 22pt geometry assertion. Both baseline failures
  were reproduced in disposable directories without overwriting task assets.
- Full desktop tests passed **3,438/3,438**, with no skipped tests.
- Desktop typecheck, repository lint and `pnpm build:js` passed. The JS build
  also built the documentation; existing bundle-size advisories were non-failing.
- `cargo check -p host-core --locked` passed for version 1.0.4. Host behavior
  was not changed; only the release version was updated.
- The real Electron NativeImage/Tray test passed on the implementation tree.
  It uses a disposable profile and destroys its own tray before exit.
- `node scripts/release.mjs 1.0.4` updated the existing version surfaces and
  passed the release-document consistency check; no tag was created.

Logs and the old-asset regression results are retained in the ignored
`.artifacts/wcsdai-icon-platforms/` directory. The fixed commit/base and native
artifact evidence are recorded in the delivery follow-up. `verify:ui:*` and
operations on the owner's installed app were not run. Windows package
inspection does not establish actual Windows visual acceptance.
