# WcSdAi 1.0.5 Windows corner repair

## Scope

The owner reported opaque rectangular pixels outside the rounded perimeter on
Windows 11 after installing 1.0.5. Keep the application version at 1.0.5 and
replace only the Windows x64 team installer after verification. Existing macOS
artifacts, the installed macOS application, profiles, sessions, credentials and
provider settings are outside this repair. No tag or GitHub Release is created.

A same-version repair is a manual download/reinstallation. The existing semantic
version checker intentionally does not announce another build of 1.0.5 as a
newer application version. Build receipts, source revisions and installer
checksums distinguish the replacement from the original Windows package.

## Acceptance

`node scripts/e2e-window-shape-native.mjs` checks the production native shape
against composed desktop pixels and hit ownership over changing background
colors. A deliberately broken CSS-only fixture must fail specifically because
opaque corner pixels hide the backdrop; an unrelated process error cannot pass
that negative control. It covers light/dark appearance, loss of focus, minimize
and restore, resize, maximize/fullscreen and plugin radius overrides.

`node scripts/e2e-windows-packaged-corners.mjs` launches the actual unpacked
Windows executable with isolated data, home and Chromium profile directories.
The updated harness records the initial window before resizing or changing its
theme, then selects light and dark themes through the real settings UI and
public IPC. It preserves native-region, DPI, corner-hit and composed-pixel
results together. Profiles and databases remain outside uploaded evidence.

Both Windows gates must pass before installer collection/upload. A failed run
may upload diagnostic PNG/JSON and the corresponding source, but cannot upload
an installable package as a successful result. The Windows-only dispatch does
not schedule macOS jobs. Hosted-runner execution is recorded with its actual
Windows version; it is not described as physical Windows 11 device acceptance.

## Current verification

Investigation is in progress. No replacement installer has been published yet.
The diagnostic candidate leaves product code and version fields unchanged.

The first native run built the installer successfully but rejected the corner
checks before collection. Its production-shape fixture had a complex HRGN,
12 DIP default, 9px first-row inset and exact 900×620 physical bounds at 96 DPI,
yet all four sampled corner pixels were RGB(243,243,243), not the colored
backdrop. The same RGB value occurs at all four outer corners in the supplied
screenshot. This is evidence of the reported visual failure, not a passing
region-only result. Additional backdrop-reference checks will distinguish the
window shell from fixture rendering before selecting the fix.

That run also exposed two harness failures: destroying the last fixture window
could cause Electron's default zero-code exit before the failure receipt
finished, and the separate backdrop exited before its ready response on
Windows. Their corrections belong to validation, not the product fix. No
installer artifact was uploaded from the failed run.

Local checks completed on the reused macOS environment: full JS build, Desktop
typecheck, lint, packaging/notices tests, corner assertion tests and documentation
checks. Windows-only probes correctly skip locally. Native results and final
repair details will be recorded after the Windows run completes.
