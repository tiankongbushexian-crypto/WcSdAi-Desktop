# WcSdAi 1.0.5 Windows corner repair

## Scope

The owner reported opaque rectangular pixels outside the rounded perimeter on
Windows 11 after installing 1.0.5. Keep the application version at 1.0.5 and
replace only the Windows x64 team installer after verification. Existing macOS
artifacts, the installed macOS application, profiles, sessions, credentials and
provider settings are outside this repair. No tag or GitHub Release is created.

A same-version repair is a manual download/reinstallation. The existing semantic
version checker intentionally does not announce another build of 1.0.5 as a
newer application version. Build receipts, source revisions and installer
checksums distinguish the replacement from the original Windows package.

## Acceptance

`node scripts/e2e-window-shape-native.mjs` checks the production native shape
against composed desktop pixels and hit ownership over changing background
colors. A deliberately broken CSS-only fixture must fail specifically because
opaque corner pixels hide the backdrop; an unrelated process error cannot pass
that negative control. It covers light/dark appearance, loss of focus, minimize
and restore, resize, maximize/fullscreen and plugin radius overrides.

`node scripts/e2e-windows-packaged-corners.mjs` launches the actual unpacked
Windows executable with isolated data, home and Chromium profile directories.
The updated harness records the initial window before resizing or changing its
theme, then selects light and dark themes through the real settings UI and
public IPC. It preserves native-region, DPI, corner-hit and composed-pixel
results together. Profiles and databases remain outside uploaded evidence.

Both Windows gates must pass before installer collection/upload. A failed run
may upload diagnostic PNG/JSON and the corresponding source, but cannot upload
an installable package as a successful result. The Windows-only dispatch does
not schedule macOS jobs. Hosted-runner execution is recorded with its actual
Windows version; it is not described as physical Windows 11 device acceptance.

## Repair and qualification

The opaque Electron 43.6 compositor fills the native region's cutouts with a
gray plate. On Windows Server 2025 build 26100 at 96 DPI, the original fixture
has a complex HRGN, four excluded corners, a 9px first-row inset and correct
900×620 physical bounds. Pointer hits already belong to the backdrop, but all
four screen samples remain RGB(243,243,243). The supplied Windows 11 screenshot
contains the same gray pixels at all four outer corners.

[Diagnostic run 38978266088](https://github.com/tiankongbushexian-crypto/WcSdAi-Desktop/actions/runs/38978266088)
verified the backdrop independently, reproduced the opaque failure and passed
all 12 corner/state scenarios with alpha composition. A second
[timing comparison](https://github.com/tiankongbushexian-crypto/WcSdAi-Desktop/actions/runs/38978701127)
proved that reapplying the native shape after showing the window or after
setting its background does not remove the defect. Both retain the gray fill;
alpha composition passes again. These diagnostic jobs intentionally fail when
the old opaque cases fail and publish no installers.

The repair enables `transparent: true` only for the Windows main window,
retaining `thickFrame: false`, the opaque theme-owned background color and the
existing 12 DIP native draw/hit shape. Application content stays opaque. No
transparent margins, geometry offsets, renderer resize handles, background IPC
changes, plugin contract changes or persisted data changes are introduced. The
native fixture imports the same frame options as production, and the packaged
probe independently checks the actual application.

Native mouse edge drags, minimum size, maximized work-area bounds, normal-bound
restoration and the complete packaged application remain release gates. The
transparent fixture's earlier `setSize` and state checks alone are not treated
as proof of pointer resizing or physical Windows 11 acceptance.

## Current verification

Investigation and final qualification are in progress. No replacement installer
has been published yet. Version fields remain 1.0.5.

The initial diagnostic run built the installer but rejected the visual checks
before collection. It also exposed two harness failures: destroying the last
fixture window could cause Electron's default zero-code exit before the failure
receipt finished, and the separate backdrop exited before its ready response
on Windows. The harness now owns fixture termination and uses an authenticated
loopback control endpoint for the backdrop instead of GUI-process stdin. The
new backdrop preflight passed on both macOS and Windows. No installer artifact
was uploaded from a failed run.

Local checks completed on the reused macOS environment: full JS build, Desktop
typecheck, lint, packaging/notices tests, corner assertion tests and documentation
checks. Windows-only probes correctly skip locally. Final repair, installer
receipts and integration evidence will be recorded after qualification.
