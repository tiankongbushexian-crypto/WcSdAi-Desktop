## Outcome

The three reported 1.0.4 defects are corrected: the AI service editor keeps its
configured-model list usable on short windows, Windows uses visible 12 DIP
corners and a 1 DIP inside perimeter, and the default assistant identifies its
application as WcSdAi while preserving the actual provider/model identity.

PR 12 passed integration checks and merged as
`4c95bd695025744ad8fe2ab57831054b9d08072e`. All three native installers passed
build and downloaded-package inspection. The local macOS application was
replaced with the verified 1.0.5 ARM package after a complete stopped-app backup;
pre-launch data/configuration and application-integrity checks passed. The
installed application launched successfully, restored the existing profile and
passed the actual service-editor acceptance check. Post-launch database
integrity and aggregate data counts matched the backup. Disposable packaged
boot/recovery validation passed independently. PR 13 published the inspected
installers and update metadata as `c5d02033140d8e9d5b01c5522c1b0abcb8ca289e`;
public-feed readback and all nine production update-feed cases passed.

## Scope and compatibility

Projects, sessions, provider credentials, permissions, profile directories and
compatibility aliases remain unchanged. Custom `SYSTEM.md`/`APPEND.md`
precedence, historical conversation text, technical package names, IPC names,
encryption identifiers and upstream attribution are preserved. Automated tests
use disposable profiles and localhost provider fixtures. During installed-app
acceptance, opening an existing service editor invoked its normal model-list
discovery. No live model inference, Test Connection action or configuration
save was performed.

The owner authorized normal PR integration, GitHub installer publication and a
local macOS upgrade. Local replacement must follow a verified stopped-app
backup. The team lane is unsigned and uses notification-only manual downloads;
it does not enable automatic installation, create a Git tag or GitHub Release,
or deploy a server.

## Failure history and resolution

- The first workspace run stopped on missing Chinese mirrors of new English
  E2E rows. A code-only rerun exposed a static traffic-light test that assumed
  a single shared import. The mirrors and import-tolerant assertion were fixed;
  full local and final CI runs passed. These were task-related failures.
- An early committed-candidate window-controls run passed its UI assertions but
  hung during unbounded SIGTERM cleanup. The harness now cleans only its owned
  detached process group or Windows PID tree, with bounded waits and failure
  propagation. The installed application is outside that cleanup scope.
- Subsequent fixture reruns exposed fullscreen polling that mutated focus,
  macOS occlusion during animation waits, a Darwin signal-zero EPERM race, and
  a cold-start stale animation promise. State polling is now read-only; only
  the fixture is restored once per hidden episode; current finite animations
  must finish in two consecutive visible observations. Cleanup uses a bounded
  PID/group-only check for EPERM. These failed runs remain superseded failures,
  not passing complete runs. The final exact-head fixture and cleanup passed.
- Team installer run `38895788902` built the Windows installer but failed before
  the native region assertions because the clean runner lacked the development
  Electron binary. No Windows installer was uploaded from that failed lane.
  The final workflow installs the locked Electron package runtime immediately
  before the Windows probe; failure blocks collection and upload. It does not
  install anything in the user's local environment. Final native acceptance
  requires the replacement run's receipt.
- The superseded Apple Silicon package passed identity/resource inspection,
  code-seal validation and two disposable packaged boot/recovery launches.
  Those receipts do not authorize publishing or installing an older candidate.
- `check:wcsdai-release` correctly refused the separate signed GitHub
  Release/automatic-updater lane because readiness and publish configuration
  remain disabled. This is intentional for the authorized unsigned team lane.
